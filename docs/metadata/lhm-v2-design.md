# LHM v2：流式追加、紧凑目录头与正常重开

实现日期：2026-11-04。本文件说明当前工作区实现；使用方法见 [接口文档](lhm-v2-api.md)，普通 RPC 见 [服务接口](service-api.md)。本次只修改 ZB 专用的 `third_party/lhm`，不修改工作区原始 LHM。

## 1. 目标与边界

支持创建存储、逐份导入命名空间及属性、正常关闭、用新进程重开、继续查询和追加。目录数量和文件数量不要求同时驻留于导入临时数组。

这是原型实现，不提供事务、失败回滚、同名树合并、异常恢复或自动重试。导入是同步管理操作，桥接 worker 串行执行；导入期间其他 LHM 请求等待。当前没有异步任务队列或跨进程导入任务状态。未完成导入可留下已成功创建的前缀。

## 2. 调用路径

```text
ImportNamespace RPC
  → NamespaceStore::ImportManifest
  → LhmNamespaceStore
  → zb_lhm_import_manifest
  → 有界 TSV 解析
  → reserve_create / commit_create
  → inode 缓存、目录头缓存、文件桶和运行时目录索引
```

流式入口逐条发布目录和文件，利用已有块缓存合并写入；它并不是先完成所有块、再一次性建立全部索引的离线排序构建器。这样无需全量父子关系表，DFS/BFS 均可，只要求父目录先出现。路径解析和逐条发布仍有 CPU 成本，尚未给出大规模导入吞吐承诺。

旧 `LHM_BULK_MANIFEST`/`zb_lhm_open_bulk` 保留兼容，仍是全量构建、两列默认属性入口。大规模或需要属性保留、追加时应使用新的流式接口。

## 3. v2 编号与物理布局

块地址、物理块换算和运行时目录文件索引编号改用 64 位运算；文件的逻辑块号限制为 `2^47-1`，避免编码类型标记和文件偏移溢出。不能将 64 位变量理解成所有 64 位数值都有效。

- 文件 inode ID：`(logical_block << 16) | slot`，slot 为 0..62。
- 目录 inode ID：`(1ULL << 63) | directory_reference`。
- 紧凑目录引用：`(1ULL << 47) | ordinal`，ordinal 从 1 开始。
- root 对外仍为 ID 1，桥接层映射到原生根引用。
- `inode_ref` 仍为 8 B，使用 48 位引用和 16 位槽位的位域；inode 仍为 256 B。
- 文件名桶内文件引用为 8 B（48 位块号、8 位槽位、8 位 generation）。

磁盘块的公共头版本提升为 2，原生位域/结构体布局限于本项目当前 Linux 编译器 ABI，不承诺跨端序/跨 ABI 直接搬运数据文件。快照标量则显式使用小端编码。v1 ID 和数据文件不能直接作为 v2 使用，本次没有旧库迁移工具。

存储由以下文件组成：

| 文件 | 内容 |
|---|---|
| `namespace.meta` | superblock、文件 inode 块、文件名桶 |
| `namespace.meta.heads` | 多目录头共享的 16 KiB 页面 |
| `namespace.meta.snapshot` | 仅正常关闭后存在的有效索引快照 |
| `namespace.meta.snapshot.tmp` | 关闭过程中构建的临时快照 |

主文件保留奇偶映射：inode 逻辑块 b 对应物理块 `2b-1`，桶逻辑块 b 对应 `2b`。主文件可能是稀疏文件，容量评估同时检查 apparent size 和实际分配空间。

目录头文件每页预留 512 B，随后放 31 条 512 B 记录。令 `n=ordinal-1`：

```text
page = n / 31
slot = n % 31
record_offset = page * 16384 + 512 + slot * 512
```

每条记录包含 64 B 公共头、64 B 目录头、256 B inode 和 128 B 名称区/预留区。ZB 名称上限仍为 64 字节，名称记录可放入该区域。文件目录项保存在独立桶中，不向紧凑目录头追加文件目录项。

读取目录头时，存储层将 512 B 记录展开成原有目录块视图，使上层属性/名称读写复用原逻辑。目录头页通过单页写回缓存完成 16 KiB 读改写；桶继续使用目录块缓存。目录记录不随改名移动，inode ID 保持稳定。删除和取消不承诺跨重启回收全部空间。

## 4. 流式导入与内存

解析器逐行读取，超长行在继续分配前被拒绝。每行至多 32 列，最大长度为 `min(memory_budget_bytes/128, 65536)` 字节。最小预算为 1 MiB。输入字符串、字段副本和路径解析不随记录总数累积。

长时间导入和快照重建每完成 64 条记录推进一次 RCU 回收，避免将旧 Masstree 对象积压到整个任务结束。

不再为新入口维护全量 `entries/files/by_parent/children/plans`。父目录关系通过已经创建的命名空间查找，重复路径由创建语义拒绝。索引池由 vector 改为 deque，避免扩容时复制全部文件索引状态；deque 的分段分配及映射表仍有开销，需计入实际内存。

`memory_budget_bytes` 约束解析工作区，不是进程或 cgroup 总内存上限。实际峰值为：

```text
常驻目录/桶索引 + 解析工作区 + 块缓存 + 桶分裂临时状态
+ 分配器/Masstree 开销 + 内核缓存/内存
```

大目录的桶增量插入和分裂复用现有 ext-hash 实现，全局深度上限仍为 20。流式并不消除此算法限制，也不保证运行时最终索引一定装入 1 TiB。

## 5. 正常关闭与重开

关闭流程：停止接收请求并等待服务调用结束；要求无未完成创建；同步目录桶、目录头页和 inode 缓存；分段写临时快照；fsync；rename 为正式快照并同步父目录；关闭存储。

快照内容包括：

- 版本和两份存储文件的设备号、文件 inode、长度；
- inode 分配高水位、已初始化块高水位、桶分配游标、目录头 ordinal 和序列号；
- 根引用；
- DFS 顺序的目录深度、边哈希、目录头引用；
- 每目录文件索引状态、哈希深度、槽位表及桶描述符；
- 流校验和与结束标记。

不保存 C++ 指针、锁、vector/deque 内存，也不复制全部文件 inode 和名称。遍历只保留 O(目录深度) 栈。重开时重建 Masstree 并分配新的运行时文件索引编号；稳定 inode ID 不变。分配器使用快照中的高水位，不扫描主文件所有块。线程局部未用完的预留 ticket 可以跳过，但不会覆盖已有 inode。

快照当前按 8 B 标量编码，大小约为 `88D + 40B + 8H + 固定头部`，D 为目录数，B 为桶数，H 为槽位数。这取代早期方案中的紧凑字段估算；后续可以压缩编码，但本版不按早期 64/16/4 B 假设报告实际大小。

重开首先持有主文件 flock 独占锁，验证快照和存储身份、版本、完整性，重建索引。服务开放前删除有效快照并同步目录，表示进入未正常关闭的可写会话。只有下次正常关闭才重新生成有效快照。异常退出后缺少快照就拒绝打开，不尝试恢复。

身份检查意味着不能只复制这些文件到新 inode 后直接打开；当前是同一存储正常重开，不提供可移植备份导入。MDS 还要求使用绑定同一绝对存储路径的 RocksDB 控制库。控制库继续承担句柄、位置和其他业务控制信息，不在本次被替换。

MDS 默认开启 brpc 的 SIGTERM 优雅退出，先停止并等待 RPC，再执行显式 Close。关闭错误会打印错误并返回失败退出码；`kill -9` 仍不受支持。

## 6. 关键代码与测试

- `src/mds/lhm/LhmStreamBridge.inc`：有界解析、属性映射、流式创建。
- `src/mds/lhm/LhmBridge.cpp`：worker、独占锁、快照发布与重开入口。
- `third_party/lhm/namespace_snapshot.inc`：目录 DFS 快照与索引重建。
- `third_party/lhm/snapshot_io.hh`：小端标量流和完整性校验。
- `third_party/lhm/persistent_store.*`：宽块号、目录头共享页、分配状态重开。
- `third_party/lhm/directory_block_store.hh`：宽运行时索引及桶索引快照。
- `tests/mds/lhm_lifecycle_test.cpp`：独立进程重开、追加、属性、共享页边界、改名/删除/扫描、损坏和异常退出拒绝。
- `tests/mds/lhm_lifecycle_rpc_test.py`：真实 MDS ImportNamespace RPC 与正常退出、重启追加。

功能测试不证明千亿规模吞吐、总内存或文件系统最大文件容量。容量目标必须在实际文件系统和目录/桶分布下进一步验证。
