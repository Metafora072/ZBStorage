# LHM 正常关闭与重开的索引快照方案

> 2026-11-04：本提案已形成 v2 实现，具体差异和当前限制见 [v2 设计](lhm-v2-design.md)。以下保留原始讨论记录，容量数字为当时字段假设。

记录日期：2026-11-02。状态：候选设计，尚未实现。

## 范围

支持批量导入或日常修改后正常关闭，再打开同一存储继续查询、修改和追加。用户已明确暂不考虑事务、异常恢复和失败批次回滚。本文不承诺断电或强制终止后可用。

现有数据块保留 inode 和文件名桶；快照补充只在内存中的目录关系、文件桶路由及分配状态。不直接保存 C++ 对象内存，不保存进程地址、锁、vector 内部指针或 Masstree 节点指针。

目录头共享布局另见 [目录头紧凑存储候选方案](compact-directory-proposal.md)。快照本身不要求重排现有数据块；共享目录头则需要新的块内槽位引用和格式版本，两项可分别实现。

## 快照内容

- 头部：格式版本、关联存储身份、快照代次、记录数量、长度和校验信息。
- 根目录及目录索引：稳定的目录引用、父目录引用、边的名称哈希和重建路由所需信息；必要名称沿用现有磁盘来源。使用明确的逻辑记录，重开时重建 Masstree。
- 文件索引：每目录状态、全局深度、单桶引用或槽位表，以及每桶块引用、局部深度、计数等元信息。运行时索引编号可在重开时重新分配，但所有引用必须一致重映射。
- 分配状态：inode ticket、高水位、目录/桶分配游标及当前分配器实际使用的其他状态；若以后支持回收，还必须包含空闲状态。
- 批次信息：如需正常关闭后接着导入下一份模板，可保存完成批次编号和目标路径。这是进度记录，不是事务提交协议。

不重复保存全部文件路径或全部 inode 属性。文件属性、文件名与 inode 引用仍由原数据块提供。

## 正常关闭

1. 停止接收修改，等待在途操作结束，冻结索引与分配状态。
2. 刷新块缓存并同步存储文件，确保快照引用的数据已写出。
3. 分段顺序序列化快照并同步文件，避免在内存额外拼出整份快照。
4. 完成快照发布，记录与存储匹配的正常关闭标志，随后关闭文件。

可使用临时文件后替换正式快照的方式发布，并同步相关目录。即使这样，也不把该流程宣称为异常恢复机制。保留新旧两份期间需计入额外磁盘峰值。

每次修改后正常关闭都需要更新快照，不能一直沿用首次批量导入的快照。

## 打开已有存储

1. 区分新建和打开已有文件，调整 bridge 和 MDS 目前拒绝已有 LHM 存储的检查。
2. 校验正常关闭标志、存储身份、格式版本及快照完整性。
3. 加载根引用和分配状态，流式读取目录、桶记录并重建内存索引；不得再次执行新库根目录分配流程。
4. 所有检查通过后才对外提供服务。

开始可写会话前，将正常关闭标志持久地置为无效，避免旧快照被误当成修改后存储的有效索引。只有完成新的正常关闭才重新标为有效。该标志可以放在配套控制文件中，不要求改变数据块布局。

遇到未正常关闭、快照缺失、版本不符或校验失败，返回明确错误，不尝试重放或回滚，也不静默使用旧快照。只校验存储身份不足以识别同一存储上的过期快照。

当前底层打开逻辑有扫描块以推算分配游标的行为。快照重开路径需要使用已验证的分配状态，避免仍然隐含全文件扫描；普通底层 Open 并不等于已完成命名空间重开。

## 容量估算

设目录数 D、文件桶总数 B、哈希槽位总数 H，候选紧凑序列化大小：

    S ≈ D × Cd + B × 16 + H × 4 + 固定头部

Cd=64 B 仅为规划假设，最终以字段设计为准；桶元信息当前为 16 B，槽位当前为 uint32_t。若扩大引用宽度，需重新计算。

| 假设 | D=32,427,097,000 | D=1,621,354,850（1/20） |
|---|---:|---:|
| 仅 64 B 目录记录 | 1.888 TiB | 96.64 GiB |
| 每目录一桶、单桶不用槽位表，80 B/目录 | 2.359 TiB | 120.80 GiB |
| 每目录两桶、两个槽位，104 B/目录 | 3.067 TiB | 157.04 GiB |

这不是实际桶分布测量，也不是快照大小的上限。重建后的内存还包括 Masstree 节点、容器、分配器和缓存开销，不能用序列化大小代替运行内存。

启动时间至少包含快照顺序读取和索引构建。S/顺序带宽仅是 I/O 理想估算，例如 120 GiB 在 1 GiB/s 下约 120 秒，不能作为完整重开耗时承诺。

## 验收顺序

1. 正常关闭后用新进程重开，核对路径、inode ID、属性、目录枚举和子树分批遍历。
2. 重开后新增对象，验证分配游标正确、没有覆盖或重复 ID；再次关闭重开核对。
3. 修改、删除、改名后重复验证，确认快照不是初次导入的静态副本。
4. 缺失、错配和损坏快照应拒绝启动；未正常关闭也应拒绝，不要求恢复。
5. 在固定数据集上记录快照大小、关闭/重开耗时及内存峰值，再评估目标规模。

快照不解决目录头空间、编号宽度、全量构建内存、批量追加入口和输入属性缺失；这些需分别改造。当前仅记录设计，没有修改原始 LHM 或运行实验。
