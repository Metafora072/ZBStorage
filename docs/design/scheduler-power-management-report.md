# Scheduler 光盘节点功耗管理汇报版设计

## 一、建设目标

本功能面向 ZBStorage 的冷数据光盘存储场景，在 Scheduler 中增加一套光盘节点功耗管理能力。系统默认模拟 10000 个光盘节点，每个节点根据访问情况在“关机、待机、开机”三种状态之间切换。Scheduler 持续统计全局功耗、各状态节点数量和状态变化趋势，为后续节能调度、访问策略评估和论文实验提供统一的控制面指标。

这项能力不是替代现有节点健康管理，而是在现有 Scheduler 全局资源视图之上，补充一层面向光盘库的大规模能耗视图。

## 二、设计思路

现有 Scheduler 已经负责集群节点心跳、健康状态、主从关系和生命周期控制。功耗管理不直接修改这些逻辑，而是新增一个独立的“光盘功耗模型”，专门管理 10000 个仿真 optical node 的功耗状态。

整体思路可以概括为三点：

- 用数组模拟大规模光盘节点，保证状态维护简单、开销可控。
- 用访问事件驱动节点开机，用周期性空闲检查驱动节点降级。
- 用独立统计视图向外提供总功耗和状态分布，不污染现有 `GetClusterView`。

## 三、总体架构

```text
                 +---------------------------+
                 |        Client / FUSE       |
                 +-------------+-------------+
                               |
                               | 读取/写入冷数据
                               v
                 +---------------------------+
                 |            MDS            |
                 |  元数据定位 optical node   |
                 +-------------+-------------+
                               |
                               | optical access event
                               v
+------------------------------+------------------------------+
|                            Scheduler                         |
|                                                             |
|  +-------------------+       +----------------------------+  |
|  | ClusterState       |       | OpticalPowerManager        |  |
|  | 节点健康/心跳/主从 |       | 10000 个光盘节点功耗状态    |  |
|  +-------------------+       +----------------------------+  |
|            |                              |                  |
|            |                              v                  |
|            |                  功耗统计、状态分布、趋势快照    |
|            v                                                 |
|  对 MDS 提供集群资源视图        对实验/监控提供功耗视图        |
+-------------------------------------------------------------+
                               |
                               v
                 +---------------------------+
                 |       Optical Nodes        |
                 |    冷数据读写与归档存储     |
                 +---------------------------+
```

架构上保持两类视图分离：

- **资源可用性视图**：由现有 `ClusterState` 维护，用于 MDS 判断节点是否健康、是否可分配。
- **功耗状态视图**：由新增功耗管理模块维护，用于统计光盘节点能耗和状态分布。

这种分离可以避免功耗模拟影响现有读写路径，也便于后续单独调整功耗策略。

## 四、核心模块

### 1. 光盘节点状态模型

系统为每个仿真光盘节点维护一个轻量状态，包括节点编号、当前功耗状态、最近访问时间和请求计数。节点状态只保存在 Scheduler 内存中，默认启动时创建 10000 个节点。

节点有三种状态：

- **关机**：无访问时的最低功耗状态。
- **待机**：短期空闲后的低功耗状态，可以理解为比开机更省电、比关机恢复更快。
- **开机**：收到访问请求后的工作状态。

### 2. 状态转换控制

节点状态由“请求触发”和“空闲超时”共同驱动：

```text
关机   --收到请求--> 开机
待机   --收到请求--> 开机
开机   --短时间空闲--> 待机
待机   --长时间空闲--> 关机
```

这套机制表达了冷数据访问的典型特点：请求到达时需要激活目标光盘节点，请求结束后一段时间内保留待机能力，再经过更长空闲时间回到关机状态以降低能耗。

### 3. 功耗统计视图

Scheduler 周期性汇总所有光盘节点的状态，形成全局统计：

- 光盘节点总数。
- 开机节点数。
- 待机节点数。
- 关机节点数。
- 当前总功耗。
- 最近更新时间。

该视图可以用于命令行测试、系统监控、实验采样和后续调度策略评估。

## 五、运行流程

### 冷数据访问流程

1. 客户端或 FUSE 发起冷数据访问。
2. MDS 根据元数据定位目标 optical node。
3. 访问链路向 Scheduler 上报一次 optical node access event。
4. Scheduler 将目标节点切换为开机状态，并刷新最近访问时间。
5. 后续 tick 周期根据空闲时间自动把节点切换到待机或关机。
6. Scheduler 持续输出当前功耗统计。

### 周期性统计流程

1. Scheduler 按固定周期执行后台 tick。
2. 功耗管理模块扫描 10000 个节点。
3. 对超过空闲阈值的节点执行状态降级。
4. 重新计算全局功耗和状态数量。
5. 可选写入运行目录下的功耗快照，供实验和排查使用。

## 六、与现有 Scheduler 的关系

本设计保持现有 Scheduler 职责不变：

- 现有心跳、健康检查、主从 failover、节点生命周期控制继续由 `ClusterState` 管理。
- 新增功耗管理只处理仿真 optical node 的能耗状态。
- 现有 `GetClusterView` 不返回 10000 个仿真功耗节点，避免影响 MDS 当前资源选择逻辑。
- 功耗查询通过独立接口提供，便于实验系统或监控系统按需拉取。

这种方式把“节点是否可用”和“节点当前消耗多少能量”拆成两个维度，为后续做节能调度留下空间。

## 七、配置与观测

建议把功耗功能设计成可配置能力：

- 是否启用功耗管理。
- 仿真光盘节点数量，默认 10000。
- 三种状态的单位功耗。
- 开机转待机的空闲时间。
- 待机转关机的空闲时间。
- 功耗快照输出路径。

观测方式包括：

- 查询当前总功耗。
- 查询三种状态的节点数量。
- 分页查看节点状态明细。
- 周期性导出功耗快照，用于实验结果分析。

所有运行日志、快照和实验结果应写入运行根目录，例如 `SCHEDULER_ROOT/logs/`，不写入仓库目录。

## 八、实验价值

该功能主要服务三个实验方向：

- **功耗趋势分析**：观察系统在批量访问、随机访问、热点访问下的总功耗变化。
- **策略参数对比**：比较不同待机阈值、关机阈值对平均功耗的影响。
- **冷热访问特征评估**：观察热点节点是否长期保持开机，冷节点是否能及时回到低功耗状态。

典型实验结果可以展示为：

- 时间序列总功耗曲线。
- 开机/待机/关机节点数量变化曲线。
- 不同 workload 下平均功耗对比。
- 不同 idle 阈值下节能效果对比。

## 九、阶段规划

### 第一阶段：功耗模型落地

在 Scheduler 内实现 10000 个光盘节点的状态管理、访问触发、空闲降级和全局统计查询。该阶段重点验证状态机和统计正确性。

### 第二阶段：访问链路接入

选择一个明确的上报点，把冷数据访问事件接入 Scheduler。建议优先在 MDS 或 FUSE 的 optical 访问路径上报，避免同一次请求被多个组件重复统计。

### 第三阶段：实验与策略评估

基于真实或仿真 workload 采集功耗数据，比较不同阈值和访问模式下的能耗表现，为后续节能调度策略提供依据。

### 第四阶段：策略增强

在已有统计基础上扩展更细粒度策略，例如热点节点保活、批量预热、延迟开机、分组功耗预算等。

## 十、方案特点

- **低侵入**：不改变现有节点健康和数据读写逻辑。
- **可扩展**：先支持 10000 个节点，后续可扩展为更多节点或更复杂状态。
- **可观测**：直接输出总功耗和状态分布，便于实验汇报。
- **可配置**：节点数量、功耗参数和时间阈值都可以按实验需求调整。
- **可演进**：第一版做统计，后续可以自然扩展为调度决策依据。

## 十一、汇报总结

Scheduler 光盘节点功耗管理的核心价值，是把冷数据访问链路中的“光盘节点是否被访问”转化为可观测、可量化的能耗状态。通过独立的功耗模型，系统可以在不影响现有读写与健康管理的前提下，实时掌握 10000 个光盘节点的开机、待机、关机分布，并形成总功耗指标。

该设计为 ZBStorage 后续研究节能调度提供了基础能力：先能看见功耗，再能比较策略，最终才能基于功耗进行调度优化。
